# 面包配送网页结构

同一私有仓库下按角色分开入口，使用同一后台同步订单，不建立三个重复项目。

| 文件夹/文件 | 用途 |
|---|---|
| customer/ | 客户登录入口介绍与维护说明，对应 /customer/ |
| merchant/ | 商家登录入口介绍与维护说明，对应 /merchant/ |
| courier/ | 配送员登录入口介绍与维护说明，对应 /courier/ |
| index.html | 共用页面骨架，包括登录、资料、工作台容器、账号恢复与客服 |
| app.js | 共用交互与按身份显示的业务功能 |
| style.css | 共用品牌、响应式与进度样式 |

角色文件夹中的 index.html 是登录介绍片段；server.mjs 按白名单路径拼入共用骨架，不能把片段单独以file://打开。根路径 / 仍是客户入口兼容地址。

服务端登录按真实账号角色验证入口；入口链接不授予权限。客户注册只创建buyer，商家/配送员由负责人通过受保护维护流程分配。浏览器会话按入口分别保存，退出一个身份不会清除另一个身份的登录。

正式部署仍须同一来源下可用的服务端、HTTPS、持久化数据库与上线验收。GitHub目录保存源码，GitHub Pages无法直接运行当前Node后端。本次未公开部署、未开放真实支付。
